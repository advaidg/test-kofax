# Tungsten TotalAgility Document Splitting Solution
## Goal
Split a large scanned document into correct logical documents while:
- keeping all pages safe
- avoiding OCR rerun
- supporting 200+ pages
- handling repeated same document types
- keeping processing time low
---
## Fastest Recommended Approach
Use **Transformation / Standard Document Separation script** and set split markers directly on pages.
```text
OCR already exists in XDoc
        ↓
Read page-wise OCR/signature
        ↓
Detect start pages
        ↓
Set SplitPage = True
        ↓
Let KTA split automatically

This is faster than exporting OCR text to C#, parsing it, and then calling page movement APIs later.

Tungsten documentation supports page/document split operations through SplitDocument, SplitDocumentAndClassify, MovePages, and CopyDocumentWithPages in CaptureDocumentService. It also confirms that CopyDocument alone does not copy pages; CopyDocumentWithPages is needed when pages must be copied.  ￼

⸻

Why This Is Fastest

This avoids:

* OCR rerun
* large text file write/read
* storing 200-page OCR in a field
* copying full documents unnecessarily
* deleting unwanted pages
* extra C# page reconstruction

The fastest point to decide splits is while KTA already has the document/XDoc in memory during Transformation/Separation.

⸻

Core Design

Step 1: Read OCR Page by Page

Use XDoc/Transformation script to access each page’s OCR/recognition text.

Create page-wise text/signature like:

Page 1 → text/signature
Page 2 → text/signature
Page 3 → text/signature

Do not modify page structure here except setting split markers.

⸻

Step 2: Detect Start Pages

For every page, calculate whether it looks like a new document start.

Use a combination of:

* document title/header
* form name
* mandatory keywords
* barcode/document ID
* “Page 1 of X”
* account/invoice/policy number pattern
* first-page layout similarity

Example:

If page contains:
- "Application Form"
- "Customer Name"
- "Date"
- "Page 1"
Then treat it as a start page.

⸻

Step 3: Handle Repeated Same Document Type

Problem:

Pages 1–5  = DocType A
Pages 6–10 = DocType A again

Keyword-only logic may wrongly merge it as:

Pages 1–10 = one DocType A

Solution:

Use second-pass/start-page similarity logic.

If page 6 looks like another first page of DocType A
→ split before page 6

Final result:

Document 1 = pages 1–5
Document 2 = pages 6–10

⸻

Recommended Split Logic

For each page:
    Extract page text/signature
    If page is first page:
        no split needed before it
    Else if page matches known new-document start:
        mark page as split page
    Else if page is similar to previous document's start page:
        mark page as split page
    Else:
        keep page with current document

⸻

VB Script Style Pseudo-Code

Private Sub Document_SeparateCurrentPage( _
    ByVal pXDoc As CASCADELib.CscXDocument, _
    ByVal PageNr As Long, _
    ByRef bSplitPage As Boolean)
    ' PageNr is usually 1-based in separation event
    If PageNr = 1 Then
        bSplitPage = False
        Exit Sub
    End If
    If IsStartPage(pXDoc, PageNr) Then
        bSplitPage = True
    Else
        bSplitPage = False
    End If
End Sub

⸻

Start Page Detection Example

Function IsStartPage(ByVal pXDoc, ByVal PageNr)
    Dim pageText
    pageText = GetPageText(pXDoc, PageNr)
    IsStartPage = False
    If InStr(1, pageText, "APPLICATION FORM", vbTextCompare) > 0 _
       And InStr(1, pageText, "CUSTOMER NAME", vbTextCompare) > 0 _
       And InStr(1, pageText, "DATE", vbTextCompare) > 0 Then
        IsStartPage = True
    End If
End Function

⸻

Similarity-Based Second Pass

Use this when the same document type repeats continuously.

Example logic:

Current page text/signature
        ↓
Compare with known first-page signature
        ↓
If similarity score > threshold
        ↓
Split here

Use lightweight similarity first:

* keyword score
* header match
* form title match
* page number pattern
* barcode/document ID presence

Avoid heavy ML unless needed.

⸻

Best Practical Similarity Score

Score +40 if title matches
Score +20 if required keyword group matches
Score +20 if “Page 1” pattern found
Score +10 if barcode/document ID exists
Score +10 if layout/header area matches
If score >= 70 → start page

This is fast and explainable.

⸻

Page Safety

Reading OCR does not lose pages.

Pages are only changed when you call split/move/delete APIs or set split flags.

Avoid unnecessary use of:

DeletePages
MovePages
CopyDocumentWithPages + DeletePages
raw PDocument.Pages.Add()

Use page split markers whenever possible.

⸻

When to Use C# Instead

Use C# only if:

* VB script becomes too complex
* you need advanced similarity libraries
* you need database-backed rules
* you need custom JSON/config-based classification
* you want to call SplitDocumentAndClassify manually

C# APIs such as SplitDocument, SplitDocumentAndClassify, MovePages, CreateDocumentWithPages, and CopyDocumentWithPages are documented in CaptureDocumentService.  ￼

⸻

C# Fallback Approach

If separation script cannot do everything:

1. Extract/store page-wise OCR or signatures
2. C# reads page signatures
3. Build split index list
4. Call SplitDocumentAndClassify

Example conceptual structure:

var splitIndexes = new List<int>();
foreach (var page in pages)
{
    if (IsStartPage(page) && page.Index > 0)
    {
        splitIndexes.Add(page.Index);
    }
}
// Use CaptureDocumentService.SplitDocumentAndClassify(...)

⸻

Storage Recommendation

For fastest processing, avoid storing full 200-page OCR unless needed.

Preferred:

Store only page signatures:
Page 1 → DocType=A, IsStart=true, Score=92
Page 2 → DocType=A, IsStart=false
Page 6 → DocType=A, IsStart=true, Score=88

Avoid:

One giant 200-page OCR field

If full text is required, use:

* external TXT/JSON
* database CLOB/TEXT
* XValues/page text extensions

Tungsten docs show text extension APIs such as SaveTextExtension/page text extension members in CaptureDocumentService member listings.  ￼

⸻

Final Recommended Architecture

KTA OCR / Transformation
        ↓
XDoc page-wise OCR available
        ↓
VB separation script detects start pages
        ↓
Keyword + similarity scoring
        ↓

        ↓

        ↓
Optional validation/review

Final Verdict

The fastest approach is:

Do split detection inside Transformation / Standard Document Separation and mark split pages directly.

Use C# only as a fallback for advanced logic.

This keeps the solution:

* fastest
* page-safe
* scalable for 200+ pages
